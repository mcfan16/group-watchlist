GroupWatchlist — App Map

A shared family watch queue. This page is a snapshot for finding your way back into the code — not a build checklist, and not part of the app itself.

What this app does

A household (mom, dad, kid) shares one queue of movies/shows. Each person rates a show 1–5 stars independently. Two views read the same ratings differently:

  • Family Queue — sorted by predicted agreement (lowest individual rating wins, so one holdout sinks a show)
  • Personal Picks — shows you rated 4–5 that the rest of the family is lukewarm on, for solo watching

Shows can be added by pasting a Rotten Tomatoes link (auto-fills details) or by hand. Swiping a row reveals Delete / Mark Watched. Built with Next.js + Supabase (shared database), deployed on Vercel.

Why it matters — lib/sorting.js, function sortFamilyView (and sortPersonalView nearby)
Every ~10 seconds the Family Queue re-fetches all ratings and re-runs this function. That one row you wrote is what actually moves a show up or down — this function is the app's original idea, in code.

To change this, start here

  • The family agreement rule → lib/sorting.js → sortFamilyView
  • What counts as a solo pick → lib/sorting.js → sortPersonalView
  • The warm color palette → app/globals.css, the :root variables at the top
  • How a Rotten Tomatoes link gets read → app/api/parse-link/route.js
  • Swipe-to-reveal Delete/Mark Watched → components/SwipeActions.js

A practice to reuse

During the build, Personal Picks was tested against real family ratings — and the original planned rule (sort by your own rating first) put a show everyone already loved above a real solo pick nobody else wanted. Trying the feature against real data caught something the plan alone couldn't (recorded in devpost/checklist.md under Revisions).

The reusable habit: as soon as a feature works, try it with real or realistic data before moving on — a spec can look right on paper and still produce a wrong-feeling result once actual numbers run through it.

Running it again

Locally: npm install, then npm run dev, then open http://localhost:3000. You'll need a .env.local with your Supabase keys — see .env.example.

Live: group-watchlist.vercel.app — redeploys automatically whenever you push to the GitHub repo's main branch.
